# Eviota — notes for AI agents and contributors

Eviota is a free, client-only static web app (React + TanStack Router, hash URLs, Vite, Tailwind v4, IndexedDB, a Workbox service worker). There is **no server**, no account system and no API key: anything that needs one is out of scope. Published to GitHub Pages; the same build works from any static host.

## Commands

- `npm install` — the committed `.npmrc` sets `legacy-peer-deps=true` to avoid an npm 10 resolver crash (`edgesOut`); keep it
- `npm run dev` — dev server
- `npm run typecheck` · `npm test` · `npm run lint`
- `npm run notices` — rewrites `public/THIRD_PARTY_NOTICES.txt` (builds once with source maps into a temporary directory to see which packages are shipped); run it after changing a dependency or anything in `public/vendor`, and read the diff
- `npm run build` then `npm run verify:static` — builds `dist/` and checks it is a self-contained static site (relative URLs, precached `index.html`, manifest, works under a sub-path)
- `npm run test:e2e` — Playwright specs in `tests/e2e` (146 specs, one of them skipped unless `EVIOTA_LARGE_DJVU` names a local large scan; desktop Chromium; builds first). Kill any `vite preview` already on port 4173 first: the config reuses a running server and skips the build
- `npm run test:e2e:webkit` — the same specs in WebKit (Desktop Safari) plus `phone.spec.ts` in an iPhone 15 profile (`playwright.webkit.config.ts`). It needs `npx playwright install webkit`, which does not work in the agent sandbox; it has never been run, so do not report it as passing.
- `python3 scripts/audit/contrast.py` and `python3 scripts/audit/unused-ui.py` — read-only tools from the checkpoint 20 audit (`docs/audit-2026-10-19.md`): colour contrast of the tokens and reader themes, and the UI components and dependencies nothing imports. They print; they write nothing, and their output is not a claim until someone has read it.

## Rules

- A new screen, dialog or control needs an accessible name and the right role. Add the screen to `tests/e2e/a11y.spec.ts` (the audit in `tests/e2e/a11y.ts` reads names from Chromium's accessibility tree). A passing audit is not a screen-reader test and says nothing about contrast.
- Unit tests live only in `tests/unit` (run by `vitest.config.ts`). Do not recreate `src/test/` scaffolding. Tests that touch IndexedDB import `fake-indexeddb/auto` and must store Node's `Blob` (`node:buffer`), not jsdom's, which fake-indexeddb cannot clone.
- Public files are referenced through `assetUrl()` in `src/lib/asset-url.ts`, never as root-absolute `/…` strings. Web Workers must be handed an absolute URL from the main thread (a worker resolves relative URLs against its own script).
- A browser spec waits for the app with `waitForApp(page)` from `tests/e2e/ready.ts` (the root route sets `data-app-ready="1"` on `<html>`), never for the benchmark: `window.__eviotaBench` exists only when the address has `?bench`.
- A scroll the app starts itself (`scrollTo`, `scrollBy`, `scrollIntoView`) takes its `behavior` from `smoothScroll()` in `src/lib/motion.ts`, which is `"auto"` when the person asked for reduced motion; a unit test fails on a literal `behavior: "smooth"`. A document that is not ours (a book in an iframe) gets `REDUCED_MOTION_BOOK_CSS`. Do not set foliate's `animated` attribute.
- Routing is hash-based (`createHashHistory` in `src/router.tsx`). Do not switch to browser history without also solving deep links on static hosts.
- The theme boot script lives in `src/lib/theme-boot.ts` and is injected into `index.html` by the `inject-theme-boot` plugin in `vite.config.ts`. Do not paste a copy into the HTML.
- Keep reader highlight theme resolution in `src/lib/reader-highlight.ts`. `getTheme()` returns the resolved theme (`paper`/`sepia`/`dusk`), never `match`.
- Never run Prettier over `public/vendor` or `public/samples` (third-party and generated files; both are in `.prettierignore`). Format only files you edit.
- A book is untrusted input. Any engine that puts book markup in an iframe must pass it through `src/lib/safe-document.ts` (scripts, handlers, remote references) before display, and any link that would leave the app must go through `requestExternalLink()` in `src/lib/safe-report.ts`. foliate-js does not do this for you: it ships `allow-same-origin allow-scripts` iframes and leaves inline scripts in place.
- `npm run typecheck` does not cover `tests/`. Run the tests to find a broken test import.
- Names kept on purpose: the IndexedDB name `folio-library`, the backup manifest value `"folio"`, and the legacy localStorage keys in `src/lib/legacy-storage.ts` and `src/lib/theme-boot.ts`. Do not "finish the rename" there without a migration.
- Brand assets (`brand/`, `public/favicon.*`, `public/icons/`, `src/components/brand/paths.ts`) are generated by `scripts/brand/make_brand.py`. Change the script and regenerate; never hand-edit them. Logos must stay text-free outlines on the four brand colours (`tests/unit/brand-assets.test.ts` enforces it).
- Do not add anything that sends reading data off the device. The only network request the app makes today is the Wiktionary/Wikipedia lookup behind "Define", and only after the reader has agreed (`src/lib/lookup-consent.ts`; Settings can take the answer back). The interface fonts are bundled (`@fontsource-variable/*`); `npm run verify:static` fails if the built CSS, HTML or service-worker rules name another host, and `tests/e2e/privacy.spec.ts` fails if the shelf, a book or Settings requests one. Any new request must be disclosed in the UI and in the README.
- Anything copied into `public/vendor`, and any image or font that did not come from an npm package, needs an entry in `scripts/make-notices.mjs` (where it came from, its licence as the files themselves say it, what is not known) before it is added. `tests/unit/notices.test.ts` fails otherwise. Do not state a legal conclusion in the notices. Eviota's own code is under MIT OR Apache-2.0 (the owner's choice, 2026-10-15; `LICENSE-MIT`, `LICENSE-APACHE`); do not change that, and do not copy code from a project under a copyleft licence (GPL, LGPL, AGPL, MPL) into `src/` or `public/` without asking the owner first. DjVu.js (GPL v2, checkpoint 14) and the CHM decoder (a port of GPL code, checkpoint 15) were removed for that reason; a CHM replacement has to come from a permissive source (the owner named the `lzxd` crate, MIT OR Apache-2.0) and be checked against a real `.chm` file.
- DjVu is decoded by `djvu-rs`, pinned exactly in `package.json` and run in `src/workers/djvu.worker.ts`. Its two `.wasm` files are not precached (a runtime rule in `vite.config.ts` keeps one on first use), and its own `THIRD_PARTY_NOTICES` is reproduced unchanged from `node_modules` as PART 8 of the notices: after changing its version run `npm run notices` and read the diff. Test files in `tests/e2e/data/` are claimed to be public domain by the `djvu-rs` repository; their README says what was and was not checked.
- Tick a checklist box only for something you actually ran. Write "not verified" for anything you could not run (browser behaviour especially). Do not add scripts that write pass/fail claims into the documents.
- `HANDOVER.md` is the source of truth for project state; `HANDOVER_PROMPT.md` is how to start a new session.
