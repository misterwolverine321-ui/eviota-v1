# Roadmap

Legend: [x] done and verified by running it · [~] reported done but not independently verified · [ ] not done · [-] removed on purpose.

## Release as a free static app

- [x] Static build: `dist/index.html`, relative URLs, hash routing, no server (checkpoint 2; `npm run verify:static` checks it, and was shown to fail on four deliberately broken builds).
- [x] Service worker precaches `index.html` and binds its navigation fallback to it (the first build bound it to an un-precached `/`). **It was never registered until checkpoint 9**: `registerServiceWorker()` ran from a React effect after the window `load` event and waited for a `load` that had already fired (seen in Chromium: no `sw.js` request, no registration, no cache). Fixed with `tests/unit/pwa-register.test.ts` (fails without the fix); in desktop Chromium the worker now registers, activates, caches all 38 precached files and a reload with the network off shows the shelf, opens an imported book and cold-starts `#/settings`. Not seen in Safari or on a phone.
- [x] Web manifest is relative (`start_url`, `scope`, icons), so installation works from a project path.
- [x] the first build's platform, Supabase, Nitro, TanStack Start and the server routes removed; no environment variables or secrets needed.
- [x] Typecheck (0 errors), 413 unit tests and the production build pass from a clean install (checkpoint 3; the extract-and-`npm ci` check is recorded in the verification log).
- [x] The real router and route tree mount in jsdom: hero on an empty shelf, page title via the router's head handling, `#/settings`, navigation by hash, not-found page (`tests/unit/app-shell.test.ts`; shown to fail when head handling is removed or browser history is restored). This is not a browser run.
- [~] First real-browser check of the new shell. Owner screenshots (2026-10-07, desktop, dark) show the hero, a shelf with sample covers, an EPUB with the shield button, and a CBR comic. Checkpoint 9 drove the production build in **desktop Chromium** (Playwright, 141): hash routing and the back button (history stays flat over repeated open/close; one Back from the shelf leaves the app; shown to fail with the old `BackLink`), page title, the 404 route, theme before any app script runs (six storage/OS combinations), light mode and persistence across reload, 360 px and 280 px windows (no horizontal overflow), offline start. Checkpoint 10 added `npm run test:e2e`; at checkpoint 15 it is 81 specs, all passing in desktop Chromium (5.0 minutes; 42 at checkpoint 11) (comics, library, PDF pages, hostile-file safe reading, PDF highlights, whole-shelf export, backup/restore including the metadata-only backup, triple-click marks in four formats, old-mark repair, the phone header). Still unchecked: iPhone/Safari (WebKit) for all of it, install (_Add to Home Screen_), a real touch device, the tab icon.
- [~] GitHub Actions workflow (`.github/workflows/pages.yml`): rewritten in checkpoint 22 (permissions split between the build and the deploy job; `checkout@v7`, `setup-node@v7`, `upload-pages-artifact@v5`, `deploy-pages@v5`, chosen from their release notes; a Dependabot file). It passes GitHub's workflow schema check and **has never run**; the first run on the owner's repository is its test. Pinning actions to commit SHAs is the owner's call.
- [x] No referrer is sent (checkpoint 22): `<meta name="referrer" content="no-referrer">`, so the _Define_ request does not carry the app's address; asserted in `define.spec.ts`, checked in the built `index.html` by `verify:static`. What Wikimedia makes of it has not been seen.
- [x] Third-party notices: `public/THIRD_PARTY_NOTICES.txt` (written by `npm run notices` from the packages that are in the built JavaScript, 56 of them, plus a hand-written entry per vendored file) ships with the site, is linked from Settings, and is guarded (`tests/unit/notices.test.ts` fails when a vendored file or a cover changes, a file is added or removed without an entry, a package version no longer matches the lockfile, the shadcn/ui entry or the licence files change, CHM code or a mention of the CHM libraries comes back, or the OpenSSL texts go missing; `verify:static` fails when the file is not in the build or when any other shipped file names a copyleft licence in words; `tests/e2e/notices.spec.ts` opens it from Settings). It records what the files say, not a legal conclusion, and says plainly what could not be established.
- [x] DjVu.js (GNU GPL version 2) removed from the repository and the site (checkpoint 14, owner's decision 2026-10-15). Between checkpoints 14 and 16 `.djvu` files were kept but not opened; checkpoint 16 brought a reader back (below).
- [x] LICENSE for Nawiri's own code: MIT OR Apache-2.0, chosen by the owner on 2026-10-15 (`LICENSE-MIT` "Copyright (c) 2026 Nawiri Contributors", `LICENSE-APACHE`, `package.json` `license`, README). It does **not** cover `src/components/ui/` (shadcn/ui, MIT). Not legal advice.
- [x] CHM decoder removed (checkpoint 15, owner's decision 2026-10-16: "strip the `src/lib/chm/` directory"). It was by its own header a port of GPL-2.0-or-later code. `.chm` files are recognised and kept without a reader (`tests/e2e/kept-not-opened.spec.ts`: imported, notice shown, downloaded unchanged, no decoder requested); a unit test fails if the removed paths or names of the old libraries come back; no CHM reader of any kind exists now.
- [ ] CHM reader again, if wanted: a port of the `lzxd` crate (MIT OR Apache-2.0) and an ITSF reader written from the published format notes, checked against **a real `.chm` file, which the repository does not have**. Not started.
- [~] DjVu reader (checkpoint 16, the owner's direction of 2026-10-17): `djvu-rs` 0.43.0 (MIT, WebAssembly) pinned exactly; its own `THIRD_PARTY_NOTICES` (38 Rust crates) reproduced unchanged as PART 8 of ours, with the author's statement recorded as the owner's screenshot of it and the file saying Nawiri did not verify it; the two decoder `.wasm` files are cached on first use, not precached. **Done and run in desktop Chromium:** a DjVu file opens, its page is drawn, the keys and taps turn it, one or two pages, search on the file's text layer, a screen-reader text beside each page, the place kept, a damaged file handled, nothing requested from another address, offline after one open, the accessibility audit and a phone-sized run (`tests/e2e/djvu.spec.ts` 14 specs, one each in `a11y.spec.ts` and `phone.spec.ts`; a colour page is checked for colour, and a large scan runs from a local path with `NAWIRI_LARGE_DJVU`, skipped otherwise: its first page drew in 3.3 s in desktop Chromium); DjVu is back in the shelf strip and the README. **Not done / not verified:** zoom, table of contents (not exposed by the package's API), thumbnails, highlights and notes; the OCR fallback; a failed-page test; a colour page and a large scan in desktop Chromium only (checkpoint 17); WebKit, Safari, an iPhone or a touch screen; any legal conclusion. The two test files are claimed public domain by the `djvu-rs` repository (claims, not findings).
- [ ] Establish the terms of the tool that made the three sample covers made by an outside tool (its metadata named the tool) and the logo concept. The owner authorized their redistribution on 2026-10-15 and the notices record that as the owner's statement; the tool's terms and the law were not checked.
- [ ] Find the build recipe of `libarchive.wasm` (its notices are incomplete: it contains OpenSSL code of an unknown version; PART 7 of the notices gives both licence texts as a fallback, which is a notice and not a finding) or rebuild it from known sources.
- [ ] README screenshots (desktop dark-mode screenshots exist from the owner; none are in the repo).
- [x] Logo and icon set built, tested and integrated (header, favicon.svg/.ico, PWA icons with a separate maskable, apple-touch-icon). Header logo seen on desktop in dark mode (alignment measured); phone, light mode, tab icon and installed icons not yet seen. See `docs/brand.md`.
- [ ] Devanagari companion wordmark (needs an exact spelling and a Nepali reader's check); stacked lockup; reverse-image and trademark search.
- [x] Project name chosen: Nawiri (renamed from Folio, 2026-10-07); renamed to Eviota at checkpoint 24 (2026-10-26, the owner's choice).
- [ ] Search GitHub and trademarks for "Eviota" for conflicts (not done; the owner approved the name on 2026-10-26 without one). Two general web searches on 2026-10-26 found no software of that name, only Eviota, a genus of small gobies (fish). That is not a trademark search.

Driven in desktop Chromium since checkpoint 11, reached from a metadata-only restore: a different file is refused, the right one is taken and the notes are there (`tests/e2e/backup.spec.ts`). Not seen on a phone.
- [x] iPhone/iPad install hint with remembered dismissal (detector unit tested).
- [x] Keep screen awake while reading; keyboard and screen-reader fixes.
- [~] Layout at 280px, 360px and desktop: checkpoint 9 measured the shelf, Settings and the reader (top bar with the shield button) in Chromium at 360 and 280 px: no horizontal overflow, every control inside the window. - [ ] PDF extract/merge keep the table of contents (OmniReader's tested implementation is to be ported).
- [ ] AI reading help without a server (on-device where the browser supports it).
- [x] Self-host the interface fonts. Inter, Inter Tight, JetBrains Mono and Lora (OFL-1.1, `@fontsource-variable/*`) are bundled and precached, so the app no longer tells Google that this browser opened it, and the 33 font files are in the precache (an offline start with them was not re-run). In desktop Chromium the shelf, a book and Settings make no request to any address but the app's own, and every font file is the app's (`tests/e2e/privacy.spec.ts`); `npm run verify:static` fails if `index.html`, a built stylesheet or the service worker names another host. Cost: the precache grew from 38 files (10475.37 KiB) to 71 (11329.11 KiB), about 854 KiB; the 33 new files are the font files. Not seen on WebKit or a phone.

- [x] Dead code removed (checkpoint 22): 41 unused UI components, 32 unused packages, `src/lib/error-capture.ts`. The stylesheet is 37 KB smaller.

## Positioning (`docs/strategy.md`)

Order follows the owner's release order. Boxes are ticked only for what was run.

- [x] Rename to Nawiri, with old `.folio.zip` backups still restoring and saved settings carried over (`legacy-storage.test.ts`, `backup-legacy.test.ts`, each shown to fail when the compatibility is removed).
- [x] **Safe local-file mode, markup engines.** Scripts, inline handlers, `javascript:` URLs, frames and remote references are removed from every EPUB section (verified against foliate's real `EPUB` loader with a hostile EPUB), MOBI/AZW3 sections (fake sections only), HTML/Markdown and CHM pages; clean books keep their exact text (the three sample EPUBs). Fails closed on unparseable sections.
- [x] Reader-facing safe mode: shield button with a panel of what was removed and which addresses were not contacted; external links ask first (panel and dialog behaviour tested in jsdom; Esc/overlay never opens a link).
- [~] External-link confirmation in the HTML, Markdown and PDF readers: **driven in desktop Chromium and covered by `tests/e2e/safe-reading.spec.ts`** (left, middle, Ctrl and Shift click and Enter each ask first; _Open link_ opens one tab with no opener; found and fixed in checkpoint 10: a middle click skipped the dialog, and PDF links could not be clicked with a mouse at all). The CHM reader has the same guard written and typechecked but **was never driven** (no CHM fixture); MOBI/AZW3/FB2 share the EPUB code path and were not driven. Not seen on a phone or in WebKit.
- [~] CSP `<meta>` enforced by browsers: **verified in Chromium** for an XHTML section in a blob iframe (with the sanitiser switched off and the meta kept, the inline script, an inline handler, a remote image and a remote stylesheet were all refused; a `<meta http-equiv=refresh>` redirect was not, so the sanitiser is the only defence for that). **Not verified in iOS/WebKit.**
- [ ] Per-book "allow remote content" (deliberately absent; owner decision).
- [x] **Universal annotation export**: Markdown (with Obsidian-style front matter), HTML (no script, no remote references), JSON (lossless) and CSV (UTF-8 BOM, formula-injection guard), per book and for the whole shelf, with chapter/page, CFI and surrounding words (`annotation-export.test.ts`, `notes-export-ui.test.ts`; found and fixed a filename bug that split Devanagari words).
- [ ] Annotation re-anchoring when a file is replaced by a newer edition (text anchors store quote + context; no re-attach flow).
- [x] A PDF highlight can be clicked to edit or delete it (before checkpoint 10 the text layer covered it, so the click never arrived; `tests/e2e/pdf-marks.spec.ts`). Mouse in desktop Chromium only; a finger on a phone not seen.
- [x] A backup restored into a fresh browser profile opens its EPUBs (before checkpoint 10 every restored EPUB said "Couldn't open this file"; `tests/e2e/backup.spec.ts`).
- [x] **Metadata-only backup moves notes onto a device's own copies of the books** (checkpoint 11). A restored book is matched to the device's own file by format, size and a content fingerprint (file name and size for backups made before the fingerprint existed); marks, sessions and collections follow it; a device without the file gets a record that asks for it. Unit tests and three Chromium specs (same file on the device, no file on the device, the zip carries no book files), each shown to fail when the logic is broken. Limits: the fingerprint is three 64 KiB windows plus the size, not a proof; a re-saved copy with different bytes is not matched; not seen on iOS/WebKit. See `HANDOVER.md`.
- [ ] Universal highlight/note/bookmark/tag experience across every format (PDF and EPUB have it; other engines vary).
- [~] **Private Shelf Search (checkpoint 18, part B).** Titles, authors and tags are searched, and books that have been opened are searched by their text. Books never opened are now indexed from the shelf for EPUB, MOBI/AZW3, FB2 and PDF, with the readers' unit numbering (`src/lib/headless-index.ts`), a visible "indexed N of M" line, and a build queue per book. A PDF hit and an EPUB hit land on the page or chapter the index counted (desktop Chromium; the EPUB case was added in checkpoint 20, with a fix for a cap that made the search look at 40 books only). **Checkpoint 21 added plain text, RTF, Markdown and HTML** (documents with no pages are cut into units of at most 24,000 characters, `src/lib/text-units.ts`), and made every hit, from the shelf or in the open book, land on the match itself and not only on its page, section or paragraph (desktop Chromium, generated files; the 1,500-page PDF case, the one-section EPUB and FictionBook, and the short landscape window are browser specs in `tests/e2e/search-landing.spec.ts`). Still missing: comics and DjVu from the shelf; notes and highlights in the search, with jump-to-location; WebKit and a phone.
- [~] **Library health and repair on import (checkpoint 19, first part).** Duplicates are found by content: the same format, size, fingerprint and bytes, whatever the name (`src/lib/book-identity.ts`, `findSameFile`). Files are checked before decoding: empty files of every format, and a missing header for EPUB, CBZ, PDF, CBR, CB7, DjVu, MOBI/AZW/AZW3 and CHM (`src/lib/import-check.ts`); the refusal is shown in the import message with its reason. Not yet: missing covers and metadata (a repair pass), broken encodings, unsearchable scans (OCR at import), a diagnosis of bad EPUB manifests, and the local repair copy.
- [~] Scanned-PDF workflow: OCR for search exists; deskew, margin crop, contrast clean-up, reading-order correction, reversible original do not.
- [ ] Offline semantic search.
- [ ] Study workspace (grouped ideas, backlinks, side-by-side comparison).
- [~] Comics: guided panel view exists; automatic panel detection correction, spread handling, direction memory are partial or absent (not audited this checkpoint).
- [ ] Local language packs (Nepali/Devanagari + English).
- [~] Private reading analytics: sessions and a stats strip exist; the specific views in the strategy and one-click delete do not (not audited this checkpoint).
- [ ] Encrypted personal vault.
- [ ] Device-aware reader modes (low-light, dyslexia-friendly, one-handed, large-print).
- [~] Accessibility pass (checkpoint 15). Done and checked in desktop Chromium: accessible names, states and structure of the shelf, Settings, the 404 page and the EPUB, PDF, comic, HTML and Markdown readers (the DjVu reader was added in checkpoint 16 and is in the audit too), read from Chromium's accessibility tree (`tests/e2e/a11y.ts`, `a11y.spec.ts`, 21 specs; `tests/unit/reader-a11y.test.ts`, 20 tests); the reader drawer is a modal dialog with a real tab list; progress is spoken once it settles; a bug in the tag editor and one in the highlight overlay were found by the browser and fixed. Not done: a keyboard path for filing a book into a collection (WCAG 2.5.7), a keyboard way into the selection popover, a current-section marker in Contents, non-colour pressed states on three toggles, contrast. **Not verified: any real screen reader, voice control, WebKit, a phone.**
- [~] WebKit/phone test setup (checkpoint 15): `npm run test:e2e:webkit` (`playwright.webkit.config.ts`: Desktop Safari for every spec, iPhone 15 for `phone.spec.ts`) lists 154 tests (146 `webkit`, 8 `iphone`, counted 2026-10-25) and **has never been run** (the sandbox has no WebKit build); `tests/e2e/phone.spec.ts` (8 specs) runs in Chromium with a 390×664 viewport, touch and `isMobile`, and found a toast sitting on the reader's Next button (fixed). Not a test on Safari or an iPhone.
- [ ] DRM-free audiobooks (`.m4b`): the browser's own `<audio>` element and a permissively licensed metadata reader. Added to the post-launch list on the owner's instruction of 2026-10-17; **no library has been named or its licence read, and no code exists.**
