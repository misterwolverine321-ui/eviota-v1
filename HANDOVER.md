# Eviota — Handover (checkpoint 24; the last zip is checkpoint 24)

This file is the source of truth for where Eviota stands. `futureplans.md` has the technical depth and a dated **Verification log** at its end; `roadmap.md` is the checklist; `docs/strategy.md` is the owner's product direction (its claims about other products are unverified). If they disagree with this file, trust the one with a dated, verified entry and fix the other.

Eviota was called **Folio** until checkpoint 3 (2026-10-07) and **Nawiri** from then until checkpoint 24 (2026-10-26). Old names survive only where changing them would lose data; see "Legacy names" below.

## What this is

Eviota is a local-first reading app for EPUB, MOBI/AZW3, FB2, PDF, comics (CBZ/CBR/CB7), DjVu scans (read, searched and kept in place; no highlights or notes yet, see checkpoint 16), TXT/RTF/Markdown, HTML (CHM files can be added and kept but are not opened: its decoder was removed for its licence in checkpoint 15; DjVu's was removed in checkpoint 14 and replaced in checkpoint 16), with annotations, search (including OCR, and a shelf search of unopened EPUB, MOBI/AZW3, FB2, PDF, plain text, RTF, Markdown and HTML books; comics and DjVu are searched inside their readers only), read-aloud, dictionary lookup, PDF page tools, collections and a light/dark theme. It was first built in an outside app builder; since checkpoint 2 it is a **plain static, client-only app** (React, TanStack Router with hash URLs, Vite, Tailwind v4, IndexedDB, a Workbox service worker). It replaces an earlier project, OmniReader, retired after an audit.

The direction the owner chose (`docs/strategy.md`): **the private reading workbench for files other readers cannot handle** — no account, no upload, no cloud AI. The goal is a **free, open-source app on GitHub, hosted free on GitHub Pages**. The owner has no money for hosting, so nothing may need a server, an account, or a key that only the owner has.

## Legacy names (deliberate)

- IndexedDB database is still named `folio-library` (`src/lib/db.ts`, with a comment). IndexedDB cannot rename a database, so a new name would strand every saved book, and copying a large library at startup is a worse risk than an identifier nobody sees. If the owner wants it renamed, it needs a copy-and-verify migration.
- Backups: the manifest's `app` accepts `"eviota"`, `"nawiri"` and `"folio"`; new backups write `"eviota"` and export `eviota-<date>.eviota.zip`. Files named `.nawiri.zip` and `.folio.zip` still restore (`tests/unit/backup-legacy.test.ts`, `backup-manifest.test.ts`, `backup-identity.test.ts`).
- localStorage keys keep the `nawiri-` prefix: `nawiri-theme`, `nawiri-reader-settings`, `nawiri-install-dismissed`, `nawiri-ios-install-dismissed`, `nawiri-lookup-consent`, the `nawiri-lookup:` cache and `nawiri-tts-position:`. Renaming them would reset every device's saved preferences and consent, so the rename to Eviota (checkpoint 24) did not touch them. `src/lib/legacy-storage.ts` moves `folio-theme`, `folio-reader-settings`, the two install-dismissal keys and per-book read-aloud positions to `nawiri-*` at startup and drops the old lookup cache; the pre-paint theme script also reads the old theme key (`tests/unit/legacy-storage.test.ts`).
- Cache names `nawiri-djvu` and `nawiri-vendor` (Workbox runtime caches in `vite.config.ts`) keep their names: a new name would leave the old cache on each device, filling space nothing reads.
- `public/samples/*.epub` and `scripts/make-samples.mjs` still carry `urn:folio:sample:*` identifiers (opaque, never shown). Regenerating the samples would change binary files, so they were left.

Each defect below was seen failing in the browser or in a unit test before its fix, and each fix was then mutated (switched off or broken on purpose) to show the new test fails for the stated reason:
  1. **The Pages rail left page 1's thumbnail grey** (`drawer/pages-tab.tsx`). Failing e2e: `reader-pages.spec.ts` "rotate rewrites the page…" (the first spec failed once; the sibling "renders a thumbnail rail" happened to pass: it is a timing race).
